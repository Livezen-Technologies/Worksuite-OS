## Findings

Severity: High = data or control crosses an organization boundary; Medium = a feature breaks or a security signal is lost; Low = misleading or cosmetic.

### Fixed

**SRV-1 · High · File locks shared across organizations** — `services/server/src/api.ts` (`/desktop/v1/files/{id}/lock`)
Repro: user in org 1 `POST /desktop/v1/files/doc-1/lock` → 200; user in org 2 same path → `409 LOCKED "locked by another user"`.
Cause: `locks.file_id` is the bare file id. Fix: the key is `<org_id>:<file id>`. Old locks expire within 10 minutes; no migration.

**SRV-2 · High · Any organization's admin controls every organization's software catalog** — `console.ts` catalog routes, `software.ts`
Repro (org 2 admin): `PUT /admin/api/catalog/apt:org1tool {"blocked":true,...}` → 200 (org 1's item replaced); `DELETE` → 204; `PUT /admin/api/catalog/apt:evilpkg {"required":true,...}` → after the org 1 device's next inventory, its heartbeat carries an `InstallApprovedApplication apt:evilpkg` command and org 1's signed policy allowlists it.
Fix: `catalog.org_id` (NULL = platform items from the operator CLI, read-only in the console). Every catalog read, reconcile, deploy, device catalog and request is scoped to the organization; another org's id or a platform item gets `409`, deleting another org's item `404`.

**SRV-3 · Medium · One malformed inventory report breaks sign-in on that device** — `api.ts` `deviceReport`, `software.ts` `installedIds`
Repro: `POST /desktop/v1/os/inventory {"collected_at":"x","hardware":{},"software":{}}` → 500, but the row is stored. Afterwards `POST /desktop/v1/os/directory/authenticate` with a correct password → 500 (`object is not iterable`), and catalog changes for the org → 500.
Fix: shape check before storing (`400`), and the reader ignores malformed lists already stored.

**SRV-4 · Low–Medium · HR webhook reaches internal addresses (SSRF)** — `attendance.ts`
Repro (org admin): `PUT /admin/api/monitoring/hr-webhook {"url":"https://169.254.169.254/latest/meta-data/"}` → 200; `POST …/hr-webhook/send` → server makes the request and returns its status.
Fix: loopback, private, link-local, CGNAT, multicast and IPv4-mapped forms are refused when saved, and again after DNS resolution before each delivery.

**SRV-5 · Low · Problem report silently dropped on an id collision** — `api.ts`
Repro: user A posts a report with `id X` → 202; user B posts with the same id → 202, but the report is discarded. Fix: B gets `409`; a resend by A stays 202.

**PKG-1 · Medium · Debian 13 signature failures not recognised** — `services/package-service/src/service.ts`
On trixie apt verifies with `sqv`. A mirror re-signed with another key reports `OpenPGP signature verification failed: … Missing key …`, which the package service's `NO_PUBKEY|BADSIG…` patterns missed, so a hijacked mirror showed up as a generic download failure instead of `SignatureInvalid`. Found because `tests/repo/apt-e2e.sh` fails on trixie (CI runs it on Ubuntu, which has gpgv). Fix: one shared `SIG_ERROR` pattern covering both, unit-tested with the captured message.

**UI-1 · Low · Greeter Network button did nothing** — `shell/src/screens/Greeter.tsx`
The button had no handler. It now opens the first-run network card. (On an installed system the greetd greeter is `services/session/greeter`; this greeter is the shell's own sign-in board.)

**UI-2 · Low · Lock screen in PIN mode says "Enter your password."** — `Lock.tsx`. Now "Enter your PIN." in en/si/ta.

**INS-1 · Medium (UX) · Install summary cut the partition plan off with "…"** — `installer/branding/worksuite/summaryq.qml`
Fixed 112 px cards hid the lines that say whether the disk will be encrypted. Cards now size to their text.

**INS-2 · Low · Check marks rendered like "√"** — the `✓` text glyph, which IBM Plex lacks. New `WsCheck.qml` draws it as a path; five uses replaced.

**BOOT-1 · Medium (UX) · Wrong disk passphrase gave no feedback** — `branding/plymouth/worksuite.script`
cryptsetup re-asks with the same words, and the splash rewrote them to the same label, so a typo looked like nothing happened. An answered prompt followed by a fresh empty one now reads "That passphrase didn't unlock the disk. Try again." Verified on the installed VM (patched theme, rebuilt initramfs, wrong then right passphrase).

**UI-4 · Medium · Light theme made text unreadable on dark backdrops** — first run (found on the installed OS after choosing Light: ~2:1 contrast), lock screen, About hero, App Center sidebar, Quick settings tiles, Display monitor tiles. The light theme is generated from palette classes, so inline backgrounds were invisible to it. Found the rest with an automated light-theme contrast sweep of every screen; all now pass except design-level items listed under Open.

**TEST-1 · `native/rs-input/test.sh` fails on libwayland ≥ 1.23** (logs `name#id`, not `name@id`); keys did reach the compositor. **TEST-2 · `tests/repo/apt-e2e.sh`**: sqv message, and the EXIT trap failed with `srv: parameter not set`.
